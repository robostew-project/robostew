# RoboStew v0.2.0 Roadmap

Status: active development

`v0.2.0` connects truthful robot-fleet state at the edge with the accelerated workloads that create, evaluate, and improve robot intelligence. It is an engineering increment, not a hosted-service announcement.

## Release thesis

A robotics control plane should answer two linked questions:

1. What is happening across the deployed fleet now?
2. Which simulation, data-generation, training, evaluation, or inference workload produced or is assessing that behavior?

RoboStew already demonstrates runtime-backed fleet truth. `v0.2.0` adds a provider-neutral, read-only Kubernetes/GPU observation path and explicit fleet-to-workload lineage without granting cloud deployment authority.

## Milestones

### M1 — Accelerated-workload truth

- Read Kubernetes nodes and pods with `get` and `list` permissions only.
- Discover GPU-requesting robotics workloads.
- Project raw Kubernetes data into a sanitized public schema.
- Fail stale observations visibly.
- Demonstrate the complete path using a clearly marked local fixture.
- Test that private Kubernetes object identities do not cross the API boundary.

### M2 — Fleet-to-workload lineage

- Associate an accelerated workload with a fleet alias and robot class.
- Represent `observe`, `curate`, `improve`, `evaluate`, and `run` stages.
- Add an evidence view that explains source, freshness, and fixture/live status.
- Define a model/policy artifact reference that is useful without leaking a private registry path.

### M3 — Evaluation gate

- Add a read-only evaluation result contract.
- Make promotion state explicit: candidate, evaluating, accepted, or rejected.
- Keep promotion advisory; do not add autonomous robot or cluster deployment.
- Exercise success, stale-data, malformed-input, and denied-action paths.

### M4 — Portability and release evidence

- Revalidate the Apple Silicon macOS quickstart.
- Validate the containerized local edition on one current Linux environment.
- Run the observer against a disposable Kubernetes cluster.
- Publish updated screenshots, architecture, capability matrix, limitations, and validation evidence.
- Cut a signed `v0.2.0` release only after all claimed paths pass from a fresh clone.

## Non-goals

- kinetic or safety-rated robot control;
- a replacement for Kubernetes, Slurm, a GPU cloud, or an experiment tracker;
- autonomous workload deployment or remediation;
- claims of production readiness or provider certification;
- fabricated benchmarks, customers, cluster validation, or hardware evidence.

## Release acceptance

The release is complete when a reviewer can clone RoboStew, run the local demonstration, see how an accelerated workload maps to a robot fleet and physical-AI-loop stage, inspect the restrictive Kubernetes permissions, run the tests, and distinguish fixture evidence from live observation without relying on project-author explanation.
