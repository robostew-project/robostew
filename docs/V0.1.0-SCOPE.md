# RoboStew v0.1.0 Scope

Status: **released on 2026-08-15**

RoboStew is the open control plane for robot fleets.

> Bring any robot. Add your stack. Govern them as one fleet.

Version `0.1.0` demonstrates robotic stewardship through a safe, local-first control-plane experience and a separately documented Azure/Dell/EVE reference deployment. It is an early engineering release, not a production robotics platform or a safety controller.

## Release audiences

- Robotics and platform engineers evaluating fleet-control architecture.
- Employers reviewing practical cloud, edge, security, and AI engineering work.
- Potential contributors looking for a bounded project they can run locally.
- Funders evaluating the technical direction and the evidence behind it.

## Release editions

### Core laptop edition

The default installation must run locally with Docker Compose and no cloud account. It will include:

- the RoboStew dashboard and API;
- a containerized state store;
- a deterministic fleet simulator;
- simulated robot health and telemetry;
- inert workload lifecycle demonstrations;
- runtime-backed status reporting;
- local validation and complete-removal commands.

The core path must not require Azure, LF Edge EVE, a second Ubuntu host, an AI subscription, NemoClaw, OpenShell, or access to the private reference deployment.

### Azure/Dell/EVE reference deployment

The public documentation may describe the validated architecture in which an Azure-hosted control plane observes and governs inert workloads on LF Edge EVE running on a Dell Ubuntu host. This is a reference deployment, not the five-to-ten-minute installation path.

The release includes generic security and warm-standby documentation, but no deployable Azure infrastructure template. It must not imply that the private environment can be recreated automatically from an empty Azure subscription.

### Optional AI advisor

AI is an opt-in advisory profile. The core product must remain useful and truthfully report its state when AI is absent or unavailable.

The optional profile may support a hosted provider or a local model after each path is validated. NemoClaw/OpenShell integration is a bounded reference capability, not a default dependency or a fleet copilot.

## Ten-minute success path

A new user on the validated Apple Silicon Mac should be able to:

1. Clone the repository.
2. Run one start command.
3. Open the local dashboard without creating cloud resources.
4. See a simulated fleet transition through healthy and degraded states.
5. Inspect telemetry, alerts, workloads, and runtime truth.
6. Stop the stack or remove all RoboStew-owned local state with one documented command.

The ten-minute target starts after Git and Docker are installed and excludes image-download time on unusually slow networks.

## Included capability claims

- Local simulated robot fleet visibility.
- Runtime-backed health states rather than hard-coded success claims.
- Human-readable workload and fleet inventory.
- Deterministic, auditable demonstration scenarios.
- Read-only and advisory safety boundaries.
- A documented Azure/Dell/EVE reference architecture backed by private validation evidence.
- Inspectable, bounded AI reference source that is not installed or enabled by the local edition.

## Explicitly excluded from v0.1.0

- Kinetic robot control or motor commands.
- Safety-rated, real-time, or emergency-stop behavior.
- Autonomous deployment, remediation, or approval authority for AI.
- Universal compatibility with arbitrary robots or robotics middleware.
- Production identity, multi-tenancy, high availability, or compliance certification.
- A promise of one-command reconstruction of the private Azure/Dell environment.
- A supported native installation that places Valkey or other services directly on the host.
- Kubernetes, managed fleet scaling, or a hosted RoboStew service.

## Release gates

`v0.1.0` was tagged after the following release gates were satisfied:

- The core laptop edition exists and follows `INSTALLATION-CONTRACT.md`.
- The designated Apple Silicon validation host passes start, demonstration, restart, uninstall, and purge tests from a fresh checkout.
- The release identifies the exact tested macOS, Docker Desktop, Docker Compose, and host architecture versions, plus the browser environment and any version detail it exposes.
- Linux, Windows, Intel Mac, and other macOS configurations are labeled untested rather than implied to be supported.
- The public snapshot passes naming, secret, endpoint, path, identity, and generated-asset audits.
- The README can take a new user from clone to a meaningful dashboard in the promised time.
- Capability and security claims match observed behavior.
- Final screenshots are captured from the public release candidate without browser URLs or private deployment identifiers.
- Apache License 2.0, notices, contribution guidance, security policy, and release notes are present.
- The public repository is created from an explicit allowlist with no private Git history.

## Truth rule

When documentation, screenshots, and runtime behavior disagree, the runtime-backed state and reproducible validation results win. Marketing language must be corrected rather than treating a limitation as completed work.
